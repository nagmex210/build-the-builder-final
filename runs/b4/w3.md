# b4 / worker 3: ARCHITECTURE A3, canned reply paths

Branch `idea/b4-3`, started from `main` (champion b1, 994d935 lineage). No archive branch was used.

## Idea

A prompt line can be reworded, shortened, reordered or forgotten by the model. A3 makes every sentence the brief
requires into fixed text instead:

1. **Extraction (build time, Azure gpt-6-astra, ~25 s, runs in parallel with datecalc and the Claude agent).**
   `builder/canned.py extract` reads the brief(s) (a clean spec or raw bank material, with memo overrides winning)
   plus the tool API file. It returns JSON with:
   - `opening`: the first words of the call, including the recording notice;
   - `lines`: sentences the brief quotes, or fixed "say that ..." statements, each with when it is due, and
     optionally a tool and outcome;
   - `goodbye` and `close_tool`.

   Nothing about a particular brief is hard-coded in the builder: every text and tool name is read from the brief at
   build time.
2. **Apply (deterministic, idempotent).** This runs from `save.py`, after harden and robust, so it applies both to the
   inner agent's own saves and to the final pass.
   - The opening becomes `on_enter: {"type": "tts"}` of the first conversation node reached from `initial_node`
     (following code/passthrough nodes), with `on_enter_first_entry_only`. The platform speaks it with no model
     call, so the model cannot reword it.
   - A line that is due after **every successful** result of a tool goes into that tool's post-hook as
     `say_now: SAY EXACTLY "<text>"`, so the sentence arrives as data at the moment it is due.
     - It reads harden's `tool_outcome`, so it never fires on a failure.
     - Failure lines stay prompt-only. They are usually due only on the last allowed attempt, and the brief's retry
       count decides that.
     - The extraction prompt forbids tool ties that depend on counts, hints or attempt numbers.
   - The goodbye goes into the close tool's description: "before you call this, in the same turn, say exactly ...".
   - A `## FIXED SENTENCES` block in `system_prompt` lists every line with its moment and says "word for word, never
     earlier".

Files: `builder/canned.py` (new), `builder/save.py` (apply after harden/robust), `builder/build.py` (start the
extraction as a subprocess at build start, wait for it with a 240 s cap before the final pass, trace event).
`runs/b4/w3_rejudge.py` is a measurement helper, explained below.

- The opening is identical on every call: "I am a digital assistant calling from Freya Bank, and this call is

- "You will receive a text message confirming this promise." was said word for word after every successful
  create_promise, including after the failed-then-retried create_promise (PUB-10).
- The goodbye was said in the same turn as close_call, before it, every time.
- Prompt-only lines (already paid, app/branch, sorry for your loss) were also said word for word when due.

## Brief-agnostic?

Yes.
- The builder code contains no sentence, tool name, outcome or rule from brief A/B.
- `canned.py` asks the model for whatever the given brief makes mandatory, and the {{var}} placeholders it may use
  are limited to the call variables.
- The hook mechanism is generic (any tool, success outcome only), and the opening goes to whatever node is the first
  conversation node.
- On a brief with no mandatory wording, `lines` is empty and only the opening/goodbye apply. If extraction fails,
  apply() gets None and does nothing, so the build is unchanged.
- Risk: if the extracted opening misses something the brief wants in the first sentence, the tts makes that error
  systematic. The FIXED SENTENCES block and the inner agent's own work cannot override a tts. The extraction prompt
  builds the opening only from the brief's opening rule.

## Recommendation

- Merge `canned.py` (+ save/build wiring). It is cheap (+0 s wall time: it runs in parallel), and on every inspected
  call the mandatory sentences were said verbatim and in order.
- Fix fast_eval separately: wait until the transcript has an assistant message after the last user message before
  judging, or re-fetch after `chat/end`. Otherwise every batch under-counts passes that end with a required sentence.
