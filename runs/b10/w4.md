# b10 w4: build stability (3x builds per brief: A, B, raw-B, C)

Base: `main` (ed64a52, the champion). The branch idea/b10-4 pointed at an old submission-prep chain (52ca09e, not based
on main and missing most of builder/), so I ran `git reset --hard main` first. That chain is still on idea/b10-5 and
harness/submit.

## Idea

Build the champion 3 times per brief (A = brief-a; B = brief-a + brief-b; rB = both raw briefs; C = held-out brief),
record every broken or degraded build, fix the cause in the builder (no blind retry), and repeat the 3x builds.
There were 36 builds in 3 rounds, all 12 builds of a round running in parallel (slots `w4-<brief>-<round><i>`).
The checker is `runs/b10/w4_quality.py <round>`: lint, hookcheck, apicheck, buildcheck, guard installed, situations
coverage, Azure model used, self-test result. Logs are in `runs/b10/w4-*.build.log`.

## What broke (round a = champion as is)

| round | builder | shipped | FAILED | agent budget hit | strong Azure calls on gpt-6 | self-test with valid chats |
|---|---|---|---|---|---|---|
| a | champion | 2/12 | **10/12** | 10/12 | 6/36 (30 fell back to gpt-4.1-mini) | 0/2 (0/0 personas) |
| b | + save retry, Azure 429 wait, agent-save shipping | 12/12 | 0 | 0 | 36/36 | 0/12 (9 in ws2: 402; 3 in ws1: platform 500s) |
| c | + ws1 self-test fallback | 12/12 | 0 | 0 | 36/36 | 0/12 (all ws1; chat endpoint 500s) |

In rounds b and c, every shipped build had lint 0, hookcheck 0, apicheck 0 and buildcheck 0 errors, the promise guard
installed (`BTB_GUARD_V1`) and 0 situation-coverage problems. No wrong id binding was found. In round a, 6 of the
FAILED builds' last files had buildcheck errors (the write tools lacked the known-ids hook) because the final pass
never reached them.
Build time: round b 389-991 s, round c 704-896 s (c includes a workspace-1 self-test round that hit platform errors).
Round a ran 679-1419 s.

Causes found (all reproducible from the logs):
1. **Freya 5xx inside the final save kills the build.** `freya.save_workflow` has no retry. One 504 on `GET
   /workspaces`, `PUT /workflow/<id>` or `POST /workflow` made `final_pass` fail and the build print
   BUILD FAILED, which happened in 10/12 builds. In 8 of the 10, the build agent had already saved a hardened version
   in the same run (by then the slot held a workflow from this run), but the stale-slot check called it "a previous
   build's" and threw it away.
2. **Silent model downgrade.** With 12 builds starting at once, Azure returned errors (rate limits) on gpt-6-astra
   and gpt-6-luna. `btb/llm.py` retried for about 18 s per model, then stepped down the chain, so 30 of 36 "strong"
   extractions (datecalc spec, A1 situations, A3 canned sentences) ran on gpt-4.1-mini. Nothing in the build log said
   so. Effect on the situations (exits) extracted for the same brief, 3 builds:
   - mini (round a): only 3-4 of 6 exits common to all 3 builds on every brief, plus spurious exits (e.g. a callback
     exit that the extraction rules exclude).
   - gpt-6-astra (rounds b, c): B, rB and C identical across all 3 builds in both rounds (6/6). A has the same
     4 core exits, and 2 exits differ in name or merge.
3. **The self-test was a no-op that looked like a pass.** Workspace 2 answers every chat with 402 Insufficient
   credits, so the trace said "self-test 1 (workspace 2): 0/0 personas failed", and the fix round and buildcheck's
   catastrophic check never ran. Workspace 1 was then also failing: chat/message 500s (63 of 84 chats in round c),
   503 "API key validation temporarily unavailable" and timeouts. A control chat turn on an older champion build
   (main-A) also hung past 200 s, so this is the platform, not our workflows.
4. **Agent budget hit (10/12 in round a).** The inner agent's `save.py` calls waited minutes on Freya (one turn took
   5 min). When the platform recovered in rounds b and c, no build hit the budget.

## Fixes (files)

- `builder/save.py`: `save_with_retry`. On a transient error (5xx, 429, timeout, connection) the save is retried with
  backoff (5 to 40 s) within a 300 s budget (`BTB_SAVE_RETRY_S`). A 4xx (invalid workflow) is raised at once. Each
  step can be repeated safely: a PUT replaces the definition, publish takes the newest version.
  `workspace_id_with_retry`, and `freya._ws` is set from `FREYA_WORKSPACE_ID`.
- `builder/build.py`:
  - fetches the workspace id once at start and passes it to every save in the run, including the agent's: one
    platform call less per save, and 2 of the round-a failures died exactly there;
  - snapshots the slot state before the run: when the final save fails but the agent saved in THIS run, it ships
    that save with a WARNING instead of BUILD FAILED (the old stale-slot protection still fails a build that saved
    nothing);
  - retries the export of the submission file;
  - prints `[model fallback]` lines;
  - prints `SELF-TEST DID NOT RUN` when no chat gave a result.
- `btb/llm.py`: on a 429, waits (Retry-After, or 5-30 s steps, up to 90 s per model, `BTB_LLM_RATE_WAIT_S`) before
  stepping down the chain, and logs every fallback (`model_fallback`) to the trace.
- `builder/selftest.py`: if no chat in workspace 2 is valid, the round is played in workspace 1 (a 402 costs
  nothing), and `ws2_error` is recorded.

Evidence that the fixes acted:
- One build retried 4 transient PUT 500s and shipped.
- 2 builds could not fetch the workspace id at start and fell back to fetching it per save.
- 36/36 strong extractions ran on astra in rounds b and c.
- 12/12 round-c builds detected the 402 and moved to workspace 1.

**Caveat:** the platform was clearly worse during round a, so the 10 → 0 drop in failures cannot be credited to the
fixes alone. The logs show the mechanism, but a clean A/B on the same platform state was not possible.

## Score

**Unmeasured.** A `fast_eval --brief B --reps 1` on w4-B-b2 produced nothing in 10 min, and single chat turns returned
500 or hung, also on the champion's own main-A. These are stability fixes and should not change agent behaviour. The
one exception: builds now get the strong model's extractions instead of mini's when the load is high, which should
help on the official scorer.

## Left / risks

- Self-simulation could not be verified in any build: workspace 2 has no credits, and workspace 1's chat endpoint
  was failing during the runs. The fallback is in place, and the trace now says when it did not run.
- A retried `POST /workflow` after a 504 may create a duplicate workflow (the platform may have created it before the
  gateway timed out). There is no list route to check. This only affects a slot's first save.
- Brief A's exit naming still varies a little (2 of 6 exits) even on astra. A second extraction plus majority vote
  would stabilise it, but this was not done.
- My 12-parallel test rig itself loads Freya and Azure. A Sunday build runs alone or as a pair.

## Brief-agnostic?

Yes. Nothing here reads or names brief content. All changes are in error handling, platform and model calls, and
trace honesty.
