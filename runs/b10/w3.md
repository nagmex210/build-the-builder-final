## Idea

I removed only what is dead or duplicated: code with no caller, values that are written but never read, branches that
cannot run, and repeated conditions. Nothing that runs had its logic changed. I did not edit the skill text
(SKILL.md / routing.md), because any change there changes what the inner Claude agent reads and cannot be shown to
leave the build unchanged.

## Proof that behaviour is unchanged

**1. Deterministic replay: exact.** `/tmp/replay.py` runs the whole post-processing chain the build applies to the
inner agent's file: `save.finish_and_save` (apicheck repair, hookcheck repair, harden, guards, robust, canned,
identity_gate, situations) followed by the final pass's lint, `hookcheck.errors`, `apicheck.missing` and
`situations.check`. It ran with the old builder (`main` copy) and the new one, on 9 real inner-agent workflow files
(A, B, rA, rB, C plus older A2/B2/C2/rB2) and the same out/ calc/canned/situations files. The Freya save was stubbed.
- Result: across every workflow, every node, transition, tool, body, prompt and step-name list is identical. The
  lint, hookcheck, apicheck and situations results are identical (0 errors in both).
- Every differing string is a hook-code string, and the only differences in them are exactly the three removed
  hook snippets above (checked string by string with difflib).
- Hook code is about 1.5 KB smaller per workflow (7,880,981 → 7,867,176 bytes over the 9 replays). That helps
  against the 110 KB per-hook limit.

**2. Full builds before (main) and after (this branch), same slots.** The inner Claude agent writes the graph, so node
*names* differ between any two builds of the same code. I compared structure with `/tmp/struct.py`:

| Slot | nodes before→after | node types | tool set | hooks per tool (pre/post) | hook variables | lint |
|---|---|---|---|---|---|---|
| A | 14→14 | same | same | same | only `tool_successes` gone | 0/0 |
| B | 14→14 | same | same | same | only `tool_successes` gone | 0/0 |
| rA | 14→15 | one extra node (agent added `closing_error`) | same | same | only `tool_successes` gone | 0/0 |
| rB | 14→14 | same | same | same | only `tool_successes` gone | 0/0 |
| C | 14→13 | the before agent wrote a separate `load_account` node | same | same | only `tool_successes` gone | 0/0 |

(`date_facts*` / `product_facts` showed up in my regex for some builds and not others. The DATE FACTS hook is in
every before and after build: `vars['date_facts']` appears 3 times in each, on the same date-facts code node and
account-lookup tool. The regex difference comes from how the agent wrote the code, not from a missing hook.)

Every slot has the same tools, the same pre/post hook on every tool, the same initial node, and the same guard,
identity and canned gate variables. The removed `tool_successes_*` variable is the only systematic difference. Node
names and counts vary the way two builds of identical code also vary, and the replay above shows the code path is
identical.

`python3 btb/test_rule_kinds.py` passes. pyflakes on builder/ is clean. The CLIs I tried still work: lint_workflow,
`situations check`, and `build.py` argument parsing.
