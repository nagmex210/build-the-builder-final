# b5 / worker 5: brief self-conflict detector (wild card)

Branch `idea/b5-5`, started from main (779b267). Note: program.md's variance rule says W5 takes an architecture
exploration, but my prompt gave me the wild-card family explicitly, and the merger had already given the
architecture families to two other workers. I followed the prompt.

## Idea
A literal judge can read two brief rules as contradicting each other. The official case that kept failing: the
mandatory opening "the call is recorded" clashes with "say recorded only after create_promise ok". It failed 3 of 7
official A/raw-A runs in b4. The builder now finds such pairs at build time and words its fixed texts so both rules
hold literally. It also checks this deterministically, both at build time and in the self-simulation.

## What changed (builder/ only)
- `builder/canned.py`: the existing A3 extraction call (one Azure call, run in parallel with the build, so no extra
  build time) also returns
  - `gated_words`: words the brief allows only after an event (tool + outcome + the rule quoted);
  - `conflicts`: rule pairs a literal reader could see as contradicting (mandatory text vs a gated word, two limits
    on one thing, once-only vs retry, never-say vs required sentence, order vs order), each with a resolution.
  The prompt also says to word the opening and the lines so no gated word appears, in that exact form, before its
  event. Meaning is kept: another form of the word or an active sentence.
  - `resolve_conflicts()`: a deterministic regex check of the opening (the text said before any tool runs) against
    the gated words. On a hit it makes up to 2 repair calls and keeps a rewrite only if the {{var}} set is unchanged.
    Hits it cannot fix are logged as unresolved.
  - `apply()`: the FIXED SENTENCES block gets "Never say the word X before <tool> returns <outcome> (brief: ...)"
    lines and a list "Rules that could look contradicting, and how both hold" (at most 6).
- `builder/build.py`: writes a trace `assumptions` event (gated words, conflicts + resolutions, deterministic check log).
- `builder/selftest.py`: new check `check_gated()`. Every self-sim chat records which tools had succeeded after each
  turn. Any agent message containing a gated word before its tool succeeded fails the persona (the message of the
  success turn is allowed), so the fix round sees it.

No brief value is in the code. The words, tools and rules all come from the extraction at build time.

## Result on this batch's builds
- The extraction found the recording-notice conflict on A, B and raw-A. All three openings came out as
  "... calling from Freya Bank, and we record this call." (first pass: "Freya Bank records this call"). The
  deterministic check found nothing left to repair: the extraction prompt already avoided the word.
- Other conflicts it logged on A (about 8-10): security retry vs "two questions", swapped-date retry vs three wrong
  answers, "offer the floor once" vs attempt 2 on the deadline, "do not repeat a refused offer" vs the prescribed
  offers, one promise per product vs retry once, "first ask" vs identity order, close_call once vs API "may be repeated".
- Self-sim: the gated check fired on no persona (the rA/rB self-test failures are ledger kinds; A/B self-test chats
  timed out under platform load, 0 valid).

## For the merger
- The opening fix is a one-line wording change with a mechanistic reason (rule (c)). It removes the literal
  "recorded" before a successful write from every call. To verify it, run the OFFICIAL A/raw-A on PUB-10 (fast_eval
  cannot show it).
- Brief-agnostic: the detector looks for kinds of rule pairs (gated word, double limit, once vs retry, order vs
  order), not for any rule of A/B. On a brief without such pairs the lists are empty and nothing changes.
- Risk: the conflict resolutions are model-written text added to the system prompt (at most 6 lines). If one is
  wrong it could steer the model wrong (e.g. it chose "do not retry close_call"). To cut that risk, keep only the
  gated-word lines and the opening rewrite.

  agent. The build should fail loudly instead.
