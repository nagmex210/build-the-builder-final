# b4 worker 2: A17 self-simulation inside the builder, scored by deterministic ledger checks (workspace 2)

Branch `idea/b4-2`, based on **main** (the b1 champion). The code idea comes from idea/b2-4 and idea/b3-4 (scenario
writer + chat runner). Their LLM judge is removed. Commits: 1d2a69b (feature), 7cad9b1 (2 plays per persona),
418d389 (fix-round gate).

## Idea
Freya's stated priority (A17): the builder simulates customer personas itself, inside the 30 minutes, and shows every
persona and result in the trace. b3 showed that LLM-judge mistake counts are noise, so here **every verdict is a
deterministic check on the bank's ledger**. The checks come from the brief (via this build's datecalc spec and the
persona writer), and nothing comes from the public cases' expected results.

## What changed
- `builder/selftest.py` (new):
  - **Personas:** 1 Azure strong call writes 6 personas from the brief. They cover pays, negotiates against
    deadline/floor, refuses, hardship/dispute routing, fails identity, someone else answers, callback, multi-product
    and one manipulative caller. Each persona is played by a practice customer; the writer sees only that customer's
    identity answers and products.
  - **Persona CHECKS:** the writer gives per-persona CHECKS in a closed, machine-checkable vocabulary: `must_call`,
    `must_not_call`, `{tool,arg,equals}` (only codes or queues fixed word for word by the brief; never amounts, dates
    or ids), `before/after`, `max_calls`. Checks that name tools not in the tool API are dropped.
  - **Generic checks (every chat):**
    - no tool result with ok=false or an error;
    - close_call exactly once and last;
    - no account tool before a successful verify_identity;
    - no identical write repeated.
  - **Date/amount checks from this build's own datecalc spec** (`out/<slot>.calc.json`, run with `datecalc.snippet`):
    - promise/callback date is a business day and not in the past;
    - promise date <= the product's band deadline;
    - promise amount >= the product's floor.
    The product comes from the account tool's result in the ledger.
  - **Workspace 2:** chats run in the second Freya workspace. The workflow is copied there as slot `st-<slot>` with
    state file `.freya-agents-ws2.json`, using the key from `FREYA_API_KEY_2` or Parameter Store `/btb/freya_api_key_2`.
    If there is no key, the chats fall back to workspace 1.
  - **Repeats:** each persona plays twice in parallel (12 chats, same wall time). A chat that hits a platform error
    early is played once more.
- `builder/build.py`:
  - After the final pass, `self_simulate()` runs: personas → round 1 → **one EDIT fix round** (Claude, Read/Edit
    only, given the exact failed checks and told that ok=false means the bank refused) → final pass + save → round 2 on
    the same personas.
  - **Keep/revert:** the fix is kept only if (failed chats/valid, failed checks/valid) is no worse; otherwise the
    build's workflow is restored and re-saved.
  - **Budgets:** self-test budget 900 s (`BUILD_SELFTEST_BUDGET_S`). Claude build budget 1260 → 720 s (builds take
    2-4 min). `BUILD_SELFTEST=0` turns the whole stage off.
  - **Trace:** every persona (title, customer, script, checks) and every chat (tools in order, failed checks,
    call_id, turn count, harness error) for both rounds, plus the fix and ship decisions.
- `runs/b4/w2/ws2_eval.sh` (harness): copies a slot's final workflow into workspace 2 (`ev-<slot>`) and runs fast_eval there.

## Self-simulation results (all in the traces `runs/traces/w2-*-20261010-2047*.jsonl`, `-2109*`, `w2-A-…-212429`)
Build 1 (1 play per persona):

| slot | round 1 failed/valid | fix | round 2 | shipped |
|---|---|---|---|---|
| A | 2/6 | 35 s | 0/6 | fix |
| B | 2/6 (9 checks) | 38 s | 3/6 (13) | reverted to build |
| raw-A | 2/6 | 40 s | 1/6 | fix |
| raw-B | 3/6 | 39 s | 2/6 | fix |

**What it caught** (all real and general, and the same kinds the fast/official scorers fail on):
- **Wrong security answers are read back, not verified.** The agent says "just to confirm, that's 4471?" instead of
  calling verify_identity. It then closes as `declined` instead of `not_verified/failed` after three wrong answers.
  This showed in all 4 builds. The fix round's prompt fix ("call verify_identity right away with every answer, never
  read it back") worked in round 2 on A and B.
- **Invented product ids** (`car_loan_123`, `CC_2288`, `PL_9912` → `unknown product_id`) on multi-product personas.
  This is exactly fast_eval B's 0/3 (PUB-11/13). Main lacks the b2 id resolver, which is on merge/b2 and merge/b3.
- **Tool calls after close_call** (add_note or create_promise → "the call is already closed"). This is fast_eval
  PUB-12's failure kind.
- **Hardship routed to the wrong queue** (restructuring instead of support when job loss is mentioned): fixed in round 2.
- **Build 2 of A:** the identity node's transition never matched after a successful verify, so the agent re-verified
  every turn and never closed. This was a real build defect, caught at 9/12 chats failing, but no fix round ran (see
  the bug below).

**Noise:**
- With 1 play per persona, round 2 showed new failures on personas that had passed round 1. B's fix was reverted
  because of a schedule_callback without `time` and close_call before notes, which were not the fixed behaviours.
  So I made each persona play twice (7cad9b1).
- The deterministic checks themselves are stable. The variance is the agent's.
- Persona checks can be wrong: in some chats the persona did not actually give three wrong answers, yet "close as
  failed" was still demanded. The fix prompt tells Claude to judge each check against the brief first.

**Bug found and fixed (418d389):**
- Under load, round 1 took about 370 s. The gate reserved a full 420 s re-test plus 180 s, so on build 2 every slot
  skipped the fix round.
- The gate now sizes the re-test from round 1's real duration. Build 3 of A confirmed it: round 1 3/12 → fix 44 s →
  round 2 3/12 (5 checks vs 6) → kept, 412 s total.

## Brief-agnostic?
Yes:
- Personas and checks are written at build time from the brief being built.
- Date/amount checks run this build's own datecalc spec.
- The generic checks use only the kit's fixed tool names (close_call, verify_identity) and the bank's ok/error
  envelope.
- No value, code, date or rule from brief A/B is in the code or prompts.

Caveat for Sunday: the chats use the kit's practice mock customers. If a hidden brief's tool API changes fields, the
mock may not fit. Chats would then error, the "too few valid chats" rule skips the fix round, and the build ships
unchanged, so it fails safe.

## Recommendation to the merger
- Merge `builder/selftest.py` + `self_simulate()`. It is cheap (6-9 min), fails safe, and gives Freya the
  self-simulation they asked for, visible in the trace.
- It pairs well with a code-side id resolver (b2 w2) and close_call ordering guard: the self-test detects those
  failures, but one prompt-level EDIT does not reliably fix them.
- Keep the 2-plays-per-persona and gate commits.
