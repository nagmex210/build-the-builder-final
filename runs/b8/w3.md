# b8 worker 3: build reliability

Branch idea/b8-3, started from main (4fa9ad0). Family: BUILD RELIABILITY (the same commit sometimes builds a broken agent).

## Idea

Measure how often one builder commit ships a broken agent, then catch broken builds in code inside the 30 minutes:
a deterministic post-build check, one Claude EDIT repair round on its exact error list, keep the better version.
While measuring I found two more ways the same commit ships a different or wrong agent, and fixed both.

## What changed (files)

- `builder/buildcheck.py` (new, no model, reads no brief). `problems(wf, api, selftest1)` returns `(errors, warnings)`:
  - every node is reachable from `initial_node` and every transition target exists;
  - every api_call body leaf has a default. An id field (`*_id` / `*_ref` / `id`) is a `{{template}}`, never a literal
    id, and a customer-like id's variable is bound;
  - every bank write with a product-like id (only operations of the tool API file count; the builder's code-only
    helper tools do not) carries the known-ids pre-hook, and some lookup records `known_ids`;
  - no unbound `{{var}}` in prompt text (task_message / on_enter / system_prompt / descriptions). A variable counts as
    bound if a call variable, a response_mapping, an extraction field, any hook code or a tool field sets it;
  - self-simulation catastrophic failure (given the round-1 record, at least 3 valid chats): every persona failed,
    or no write tool was called;
  - warning only: a tool API operation on no reachable node (a brief may not use every tool).
  CLI: `python3 builder/buildcheck.py <wf.json> <api.json> [selftest1.json]`.
- `builder/build.py`:
  - `build_check()` runs after the first final pass. On any ERROR it runs one Claude EDIT round (2–6 min, bounded by
    the time left) with the exact list. It then runs the final pass again and keeps the repair only if the error count
    drops; otherwise it restores the build. All of this goes to the trace.
  - **rebuild**: if the build agent wrote no workflow file (agent error, quota, not logged in) and more than 10 min
    are left, it runs one rebuild.
  - **no stale success**: if nothing was saved in this run, the build fails loudly. Before, it printed the previous
    build's `workflow_id`/`agent_id` from `.freya-agents.json` as this build's result. I saw this live: with the inner
    Claude not logged in, w3-A "built" in 53 s and exported the old agent.
  - **clean slot** (`clear_slot`): at build start, every old file of the slot in `out/` and `scratch/` moves to a
    tmp dir outside the kit. That covers `<slot>.workflow.prev.json`, `<slot>.gen.py`, `gen_<slot>/` and `<slot>-src`.
    The build prompt also says never to start from an earlier workflow or generator. Seen in round 1: w3-rA said
    "built from this slot's own earlier version (out/w3-rA.workflow.prev.json)" and w3-rB ran the previous batch's
    `out/w3-rB.gen.py`. So the same commit shipped an older builder's agent. On Sunday the slot is new, so local test
    builds must start the same way.
  - After the self-simulation, buildcheck runs again with the round-1 record (catastrophic check) and the trace logs
    the shipped error count.

## Broken-build rate

| measurement | builds | broken (buildcheck ERROR) | notes |
|---|---|---|---|
| historical: every `*.workflow.json` in all worktrees' `out/` (b4–b8 builds, other slots) | 59 | 5 | 2 pre-harden builds without the ids hook (main-A3/rA3); 1 self-sim catastrophic (main-A2: 12/12 personas failed); 2 unbound prompt vars (w1-rB `{{days_late}}`, `{{past_due}}`; w2-rA `{{amount_state}}`): the model reads the raw placeholder |
| round 1: champion builder + check, 9 builds (A×2, B×2, rA, rB×2, C×2), slot files left from earlier batches | 9 | **2 before repair → 0 after** | w3-A and w3-rB both had `{{product}}` in the debt-statement line with nothing setting it. Repair round: 6 turns, 12–17 s, `1 -> 0 errors`, kept. A further 2/9 builds (rA, rB) started from STALE slot files (old prev.json / old generator) |
| round 2: + clean slot, the same 9 builds | 9 | **0 before repair, 0 after** | every build wrote its own `out/<slot>.gen.py`; no stale reuse |

So: about 2/9 builds per round carry a static defect that the model then sees raw (unbound variable; 8% of all
historical builds). The repair round fixes it in under 20 s, so the shipped rate was 0/18. Stale-slot reuse was
2/9 in round 1 and 0/9 after the clean-slot change. Neither of the two named past failures was static:
- b5's dropped `customer_id` is already repaired by apicheck in main;
- b7 raw-B's invented product ids: I checked the b7 rB workflow (`repo/out/main-rB.workflow.json`) and it passes the
  static check, with no literal ids in any prompt. That failure is runtime model behaviour, and only a working
  self-simulation can catch it (see below).

Build time: round 1 131–228 s; round 2 183–301 s (with the check plus at most one 15 s repair). The inner agent now
finishes in about 100–125 s.

## Self-simulation does not run (important for everyone)

Every self-test in this batch printed `self-test 1 (workspace 2): 0/0 personas`. Workspace 2 answers
`POST /api/v2/chat/message -> 402 Insufficient credits` (seen in out/*.selftest1.json of all workers since at least
b6–b7; most selftest1 records across worktrees have n=0). The A17 self-simulation, its fix round and my catastrophic
check have therefore been a no-op. The trace still claims a self-test ran. Workspace 2 needs credits, or the
self-test needs a fallback to workspace 1 (with the queue cost).

## Brief-agnostic?

Yes. buildcheck reads only the workflow's own structure, the tool API file's operation names, and the shapes of
template variables and id fields (`*_id`/`*_ref`). It contains no tool body field name, rule, value or outcome from
a brief. The repair prompt only lists the check's errors. The clean-slot step only matches the slot's own name. The
rebuild and stale-success changes are control flow.
