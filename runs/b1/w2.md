# b1 / worker 2: workflow structure and routing

## Idea

Give the builder a fixed, brief-agnostic **graph recipe** and a **structural lint** so that every build has the
same reliable skeleton, with transitions driven by tool results instead of `matches_intent`:

```
setup(code) → opening(conv: callback, close) → identity(conv: verify, close[, transfer])
  → load_account(api_request, passthrough) → prepare(code, passthrough: all facts as strings)
  → negotiate(conv: promise, transfer, note, close) → hang_up(end_call, silent, message_mode none)
```

- Who is on the line: an extracted enum (`party`, default `unknown`) routed with `equals`.
- Identity → account: `verify_identity_response.data.all_verified` tested as `"true"` and `"True"`.
- Every stage that can close has the close tool. The first transition of that node goes to `hang_up` on the
  close tool's result (`close_call_response.data.ok` true/True). Nothing else hangs up.
- One negotiate node for every product. The code node builds an ordered product summary, so there is no node per product.
- Every api tool gets a post-hook with `data.what_to_do_next`.
- Iteration 2: a pre-hook must never redirect `config['url']` to localhost to "block" a call that breaks a rule.
  The platform refuses that ("Localhost URLs are not allowed") and the turn breaks; iteration 1's A and B builds did this.
  To stop such a call, drop a required body field instead (the bank answers `ok:false` and records nothing) and
  explain why in `what_to_do_next`.

## What changed (files)

- `.claude/skills/build-phone-agent/routing.md` (new): the recipe, the exact transition JSON patterns, tool and hook
  rules, when to use global nodes.
- `.claude/skills/build-phone-agent/SKILL.md`: step 3 reads routing.md; step 4 follows it and runs the lint before saving.
- `builder/lint_workflow.py` (new, standard library only): reports as ERROR unknown targets, top-level `and`,
  boolean `equals` without both spellings, passthrough without `always`, `end_call` nodes with transitions or
  without a terminal, `pre_actions` on conversation nodes or `tools` on code/api nodes, mappings inside
  pre_actions, hooks or code containing `{{ }}` or that do not compile, localhost URLs in hooks, a close tool
  with no transition to an end node, and nodes with no path to an end. Its WARNs: unreachable nodes, mapping
  paths without `data.`, `const`, low `max_node_turns`.
- `builder/build.py`: after the build, runs the lint on `out/<slot>.workflow.json` and writes the result to the trace (`event: lint`).

## Failures left (clean calls, not platform)

- Date and calendar logic: next-business-day callback said as "tomorrow" (PUB-02); a date after the deadline was accepted
  (PUB-04 asks_back: 6 Nov); a holiday was not moved to the next business day (PUB-07); wrong dates in B PUB-13 asks_back.
  These belong to the code-step family: the builder's `prepare` code computes them, but the prompts still let the model choose.
- PUB-09 (raw-A, two styles): no restructuring transfer; the agent made its own arrangement.
- PUB-03: after the third wrong answer the agent did not submit it to verify / did not say "app or branch".
- PUB-08: the "payments can take one business day" sentence was missing.
- PUB-10: the judge flagged "this call is recorded" in the opening as "recorded before a successful call". This is judge noise.
- PUB-06 raw-A: the floor was offered twice. Both A and B also had a few calls cut short by the platform mid-call.

## Brief-agnostic?

Yes. routing.md and the lint name only the seven tool names, which are fixed by the competition, and API/platform
mechanics (`data.` paths, true/True, passthrough, end_call). No rule, value, date, holiday, outcome code or reason
from brief A/B is in the builder: field names, enums, outcomes and reasons are explicitly "from the brief and the
API file you were given". Note: the generated workflows themselves contain the brief's holidays and outcome codes,
because the builder read them from the brief at build time. That is intended.

## Hypotheses for next batch

- (H) The skeleton plus the lint makes builds structurally uniform and fast (about 5-9 min). The remaining failures
  are in date choice inside negotiate. A deterministic `create_promise` pre-hook guard (drop a field when the date
  or amount is outside what `prepare` computed) should fix PUB-04/07-type failures, together with a node-level
  "allowed dates" list. This needs a healthy sandbox to measure.
- (H) The lint should also be run inside the merged builder whatever skill wording wins: it is cheap and catches silent platform drops.
