# b1 / worker 5: conversation robustness

## Idea
Make every built agent handle how customers talk (numbers in two parts, corrections, amounts/dates in words,
questions back, small talk), **deterministically, in code**, so no build can forget it:
1. `builder/robustness.md`: a brief-agnostic block ("How customers talk"). `build.py` adds it to the workflow's
   `system_prompt` in a post-step after the Claude build and re-saves the same slot. The dialogue model sees it in
   every node. It covers: join pieces and never check a partial value; the last correction wins; convert words
   and digit-by-digit speech; answer a question back briefly (nothing about the debt before identity), then ask
   again; small-talk dates and amounts are not offers; read the value back before recording; one question at a time.
2. Same post-step: every *classification* extraction field (`enum_values`, or a description listing 3 or more quoted
   labels `'x':`) gets an `INTENT_GUARD` sentence: only an explicit statement counts. A question back ("could the
   deadline be later?"), small talk or hesitation is not an action category, so the field takes the neutral value.
   This was added after reading a transcript: on PUB-04 [talkative] the customer asked "is there any way to extend
   the deadline?" and `cust_topic` became `restructuring`, which sent the customer to a transfer instead of
   recording the promise.
3. SKILL.md: a "Customers talk like people" section. Extraction descriptions use the final, corrected value,
   converted from words and joined from pieces. No routing on half answers. `max_node_turns` of at least 8 on nodes
   that collect values.
4. `btb/fast_eval.py` (harness fix): the platform answered **503** to about half of the chat turns during this
   batch, and fast_eval only retried 502 and 504. Now a 503 is resent only when the customer's message was not
   recorded; otherwise it waits for the reply as with 504.

Files: `builder/build.py` (add_robustness post-step, INTENT_GUARD), `builder/robustness.md` (new),
`.claude/skills/build-phone-agent/SKILL.md`, `btb/fast_eval.py`.

## Brief-agnostic?
Yes. The block and the guard name no rule, value, date, code or field from brief A/B. The guard finds
classification fields by their shape (an enum, or quoted labels), not by their names. Every customer style
comes from the README's list of final customer styles.

## Build time
- A: 561 s. B: 402 s.
- rA and rB: **stopped by me after more than 40 min**, over the 30-min limit. The baseline Claude-SDK builder spent that
  time on live chat tests against the down platform (sleeping and retrying). The **rB builder also started
  `tools/run_cases.py`** (the official scorer, which workers must not run), and I killed it. The robustness post-step
  was then applied to their last saved workflows by hand (`add_robustness`), and those were evaluated.
  -> Advice for the merger/next batch: the builder needs a hard internal deadline (for example 20 min for the
  agent, then save and stop), and the skill/prompt must forbid run_cases.py and long platform tests.

## Failures left
- PUB-03: the agent asks for an answer again after the bank says no attempts are left (identity-limit logic, not speech).
- PUB-07: refusing a non-business day and moving to the next business day. Once misrouted to restructuring under
  [corrects] even with the guard.
- PUB-08 [talkative]: misses the "can take one business day to appear" sentence.
- B: duplicate tool calls on multi-product cases (repeated create_promise/add_note).
- Judge strictness on "says it is a digital assistant when asked" when the agent already said so in the opener.

## Verdict
The idea is cheap (no model call, under 1 s), deterministic and brief-agnostic. The guard fixed the
transcript failure it was written for (PUB-04 ledger is now correct 2/2). Because of the outage I could not show a
clean score gain. I recommend merging it on top of whatever wins, then re-measuring when the platform is stable.
