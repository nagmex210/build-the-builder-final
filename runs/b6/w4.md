## Idea (M4 / M18 / M29)

Official PUB-03-type failure (0/4 on merged b5, 1/2 champion): before identity passes, the agent disclosed an
(invented) amount / "past due", and closed with the wrong outcome. The verdict of each identity answer was the model's
own inference from raw fields (`verified`, `wrong_answers_left`, `all_verified`) plus the inner build agent's hook.
Now CODE decides the identity state after every identity-tool result and the prompt/structure read only that.

## What changed (all brief-agnostic)

- `builder/identity_gate.py` (new), applied in `builder/save.py` final pass after harden + canned:
  - identity tool = the api tool whose name contains verif/identit. Post-hook appended (after harden's) writes
    `identity_state` (vars + result) = `passed` / `asking next` / `retry <field>` / `failed`, decided from the
    response's own keys (all-verified key = name containing verif+all; attempts-left key = name containing
    left/remain; `hint`; ok=false unreadable), plus one `say_next` instruction per state and an `identity_status`
    NOT VERIFIED line ("you know nothing about the account, never guess a figure even if the customer names one")
    for every state but passed. `failed` carries the brief's referral sentence verbatim (from canned.json lines,
    i.e. read from the brief) and "call <close tool> now with the brief's outcome for a failed identity check".
  - terminal node `identity_failed`: every node holding the identity tool gets a transition (after its close route,
    before the others) on `<tool>_response.data.identity_state == failed` OR var `identity_state == failed`. The node
    says the referral sentence if not said yet and calls the close tool; it inherits the close -> hang-up route; the
    close tool is copied in if it is node-level only.
  - `## IDENTITY GATE` block in the task_message of every pre-identity node (identity nodes + the opening node):
    follow say_next; until passed never say/guess an amount, product, debt, balance, due date, "late/past due", or
    "verified"; a "how much do I owe?" gets "the security check comes first" + the pending question.
- `builder/selftest.py`: `check_privacy` post-turn lint in the self-simulation: any agent message before the turn in
  which the ledger shows the identity tool's all-verified flag true fails on a money/debt word (currency + number,
  number + currency word, x.xx, past due / overdue / arrears / balance / you owe / minimum payment ...). Generic
  words only, no brief values. Failures feed the existing fix round like the other deterministic checks.

Local test: hook executed on the 6 response shapes (wrong, right-not-all, 0 left, swapped hint, unreadable, all
verified) -> retry / asking next / failed / retry / retry / passed; apply() idempotent; lint_workflow 0 errors.
All four builds got the route + both gate blocks (A, rA, B, rB: nodes ... identity_failed, gate in opening+identity).

## Brief-agnostic?

Yes. The identity tool is found by name (verif/identit); the verdict comes from the response's own key shapes
(all-verified flag, attempts-left counter, hint, ok=false). The referral sentence and close tool name come from
canned.json, which is extracted from the brief at build time; if there is none, the text falls back to "as the brief
says". The privacy lint uses generic money/debt words only. No brief value, outcome code, or rule is written
into builder/. Outcome codes are left to the model ("the brief's outcome for a failed identity check").
Limitation: a brief whose identity tool has no attempts-left counter never reaches `failed` from code (the brief's own
attempt rule then stays with the model, as before).
