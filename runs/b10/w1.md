## Confirmed bugs, fixed

### Time budget, process exit, races (builder/build.py, builder/selftest.py, builder/save.py)

| # | bug | evidence / repro | fix |
|---|---|---|---|
| b1 | **A stuck self-test chat keeps the build process alive after BUILD END.** `run_tests` gives up on a chat after its timeout. But the chat ran in a `ThreadPoolExecutor`, whose workers are joined at interpreter exit. A chat stuck in the platform's 5xx retry loop (chat_turn can retry 6 × 120 s plus 12 polls) therefore held the finished build open, which can push it past 30 min. | b1: the process exits 25 s after a 2 s timeout on main, 2.1 s on the branch | daemon threads plus a join with the deadline. A crashed chat is now reported as "chat crashed", no longer as "did not finish in time". |
| b2 | **Self-test round 1 ignored the time left.** Round 1 always got ROUND_S = 420 s; only round 2 looked at `left()`. A late build (slow agent + rebuild, or a buildcheck repair round) ran up to ~420 s past BUILD_TOTAL_S. Round 2 had `max(120, min(ROUND_S, left()))`, which is still > left when less than 120 s remain. | b2: with 150 s left, round 1 gets 420 s on main | Round 1 is skipped with "SELF-TEST DID NOT RUN: only N s left" when there is no room. Round 1 and round 2 get `min(ROUND_S, left() - 60)` and are skipped below 120 s. If round 2 can't run, the build is restored (an untested fix is never shipped). |
| b3 | **Unlocked read of `.freya-agents.json` while a parallel build rewrites it.** `freya.save_workflow` truncates and rewrites the file under save.py's lock. build.py's end-of-run read and selftest's ws1 fallback read it without the lock, so they can see an empty or partial file. The result is a JSONDecodeError at the end of a good build, with no workflow_id line. The workspace-2 state file `.freya-agents-ws2.json` had no lock at all (lost entries mean a new ws2 workflow is created each time, and a workspace holds a limited number). | b3: 355 of 10192 reads failed during continuous saves on main, 0 on the branch | `save.locked_save` (exclusive) for all saves, ws2 included, and `save.read_state` (shared lock) for every read |
| b4 | **`clear_slot` treated '-' as a word boundary**, so slot `brief-a` moved away the files of slot `brief-a-raw`: its workflow.json, calc.json and canned.json. Slot `a` moved `w1-a.calc.json`. This happens in practice: w4 is building `w4-A-a1/a2/a3` in parallel this batch. On Sunday the slot is the brief's file name, so prefix-related hidden brief names would hit it. If a build started while the other was in its agent phase, the other build would lose its calc/canned/situations and possibly its workflow file. | b4 | '-' is never a boundary, and '_' is not one after the name. All own stale files are still moved (`<slot>.*`, `gen_<slot>.py`, `gen_<slot_with_underscores>`, `<slotnodash>.*`). |
| b5 | **No retry on a platform 5xx for any save** (final pass, fix round, restore) and none for the export GET. In b9 main-B, `final pass failed: PUT … -> 504` hit the fix save AND the restore. The build then printed the slot's older version as its result, and Freya held whichever PUT had landed. The merger's b9 retry (9bd7f75) was only in merge/b9, which was not kept. | b5 (stubbed PUT answers 504 twice, then succeeds) | `locked_save` retries a 5xx up to 4 times, sleeping 10/20/30 s outside the lock. A PUT of the same workflow is idempotent. The export retries a GET 5xx twice. |
| b6 | **A self-test that never ran was reported like a pass.** In 28 b8 build logs workspace 2 answered 402 to every chat, and the trace said `self-test 1 (workspace 2): 0/0 personas failed a check`. The ship event then logged `why: "no failed check"`, a wrong branch: n_failed was tested before n. The submitted trace claims a test result that does not exist. | b6 | With 0 completed chats the build prints and logs `SELF-TEST DID NOT RUN: 0 of N persona chats completed (<harness error>)` and `why: self-test did not run`. Otherwise it prints `x/n completed chats failed (k of N did not complete)`. |

### Date/amount code (builder/datecalc.py; the code runs inside the phone agent)

| # | bug | repro | fix |
|---|---|---|---|
| r1 | A percent floor was cut to cents before the brief's own rounding: 10 % of 100.01 rounded up to 1 gave 10, should be 11. The floor could end up below the rule. | r1 | `round_amt` does the rounding. Cents are rounded only when the brief gives no rounding. |
| r2 | `min_amount` was applied before rounding, so rounding down undid it: 1 % of 1000, min 25, down to 10 gave 20. | r2 | round first, then take max(min) |
| r4 | The cut-off time was a string compare: `'15:00' >= '9:30'` is False, so an unpadded cut-off never applied. Worse, datecalc's own selftest then reported "cut-off not applied", and the whole datecalc failed (the build ran with no code steps). `hm_of` also needed `now[13] == ':'`. | r4 | `hm_norm()` parses H:MM / HH:MM / H.MM / HH:MM:SS. `hm_of` uses it, and so does the datecalc selftest. |

No behaviour change on real specs: on all 83 `out/*.calc.json` specs in every worktree, the datecalc selftest gives
the same result, and `floor_for` gives the same value on 24 900 random products with main's code and with the
branch's code (`/tmp/w1_floordiff.py`: 0 diffs). None of those specs combines percent + round-up with sub-cent
values, min + rounding, or an unpadded cut-off. These are edge cases a hidden brief can trigger.

## Unconfirmed, or confirmed but not fixed (brief-dependent or out of family)

- r3 (repro kept, not fixed): with a calendar-day deadline and "back", a call on a Saturday with a 1-day deadline
  rolls back to Friday, which is before today. Whether that is wrong depends on the brief (calls on weekends?).
- Same slot for two hidden briefs: the submission form uses the brief's file stem as the slot. Two hidden briefs with
  the same file name in different folders would build into ONE workflow. Use `btb/submit.sh <brief> <api> <name>`
  with distinct names on Sunday (submit.sh already supports this).
- `scrub_file(trace)` is not in a `finally`: a crash before BUILD END leaves the jsonl trace unscrubbed (submit.sh
  scrubs it afterwards anyway). A truncated key (`res[:400]`) or a JSON-escaped key is not redacted.
- selftest check semantics, found by the subagent with repros under /tmp/bh2 (not fixed: these only matter once the
  self-test runs, and they change what is judged a failure):
  1. `verify_identity` with ok=true but verified=false counts as an identity pass for the order check.
  2. Gated words with outcome "" are never checked.
  3. Floor and deadline are checked per promise call, not per product, so a correct 2-part plan fails.
  4. `now` is read from a hard-coded `now` variable, not the spec's `now_variable`, so all date checks are skipped
     for a brief with `call_time`.
  5. Personas are always drawn from public-test-set.json customers (brief C personas played by PUB customers).
- `situations._find` matches node names by substring both ways. `canned.close_structure` can turn an `and` group into `or`.
- Default-executor threads (write_personas in `run_in_executor`) are also joined by asyncio.run's shutdown. llm.py has
  a 180 s HTTP timeout per call, so this is bounded, but not by the build budget.

## Brief-agnostic?

Yes. No brief value, name, date, code or rule was added. All changes are harness and pipeline mechanics: timing,
locks, retries, trace honesty, prompt assembly, and the generic rounding, min and time-parsing order in the date/amount
library. The datecalc changes do not change any result on the 83 real specs. They only change edge cases that were
wrong for any brief.
